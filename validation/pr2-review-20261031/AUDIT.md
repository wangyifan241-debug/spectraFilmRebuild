## Actual pixel path and contract

* `engine/src/io/raw_decoder.cpp:46-58`: LibRaw compatible16 uses output_color=4 (ProPhoto), linear transfer, 16-bit decode converted to float32. Headroom mode uses float conversion before uint16 clipping and has explicit sensor/format restrictions. Neither is an encoded sRGB input.
* `engine/src/desktop/preview_host.cpp`: PreviewHost supplies scene-linear ProPhoto to the render engine. Windows Vulkan is the product render path; host CPU colour conversion is not a CPU fallback for film simulation. Existing Vulkan/host numeric contract tests cover the boundary; macOS parity is not established by Windows tests.
* Engine film/paper operations and measured resources stay unchanged. Retained frame pixels are opaque encoded ProPhoto RGBA16 (or legacy sRGB); the quantized engine output is already bounded to 0..1. Lost headroom at that boundary cannot be recovered by an ICC tag.
* Qt applies develop in encoded working space, crops/straightens/turns/flips and resizes RGBA16, then converts through the frame-owned host display transform, then quantizes PNG8/JPEG8. TIFF16/PNG16 preserve 16-bit output precision. PNG/JPEG use Qt plugins; TIFF uses the checked streaming writer. Files are staged adjacent to the target and atomically published without replacement.
* Display and current exports both target sRGB; OS monitor calibration is outside this conversion. P3/ProPhoto **export** must be independent of display selection, with a destination-owned matrix, CCTF, ICC and gamut policy. Reuse host OutputTransform/icc_for, retain 128-row conversion, transform actual samples before tagging, preserve the current sRGB gamut policy. Reject unsupported space/format pairs. Add selector only after independent decode/ICC/white/TRC/ramp tests pass. This review does not claim selectable wide-gamut export is implemented.

Reproductions and results are recorded in RESULTS.md as they run. No fixture-dependent skip, synthetic RAW, old artifact or Linux result is evidence of real-camera Windows success.
