# SpektraLab Windows 材料库审计与扩展研究

审计日期：2026-10-30。此报告先于材料扩展；审计本身没有替换资源或修改物理算法。
原始本地 HEAD：`fd891c6bc5eb350387602deb5c1ef9b6dcdab948`，包含当时未提交的 Windows 移植；后来按用户指示保存为基线 `b2575d4`。

## 结论

| 数据集 | 胶片（filming） | 印相材料（printing） | 总数 | 与本地的关系 |
|---|---:|---:|---:|---|
| SpektraLab 原始上游层 | 20 | 8 | 28 | 不是 28 款胶片；印相材料包含电影拷贝正片 |
| SpektraLab 产品扩展层 | 5 | 1 | 6 | 四款黑白负片、CineStill 别名、Multigrade 银盐相纸 |
| 当前 Windows 实际程序包 | 25 | 9 | 34 | 与上述两层逐文件 SHA-256 全部一致，没有缺包或旧副本 |
| spektrafilm main | 20 | 8 | 28 | ID、名称、版本全部已包含；无缺失材料 |
| spektrafilm dev / experimental | 22 | 9 | 各 31 | 三个新黑白 ID；非稳定分支，不自动替换 |
| spektrafilm couplers-tuning-iterations | 20 | 8 | 28 | 无新增 ID；实验数据，不作默认更新源 |
| darktable 当前数据包 | 22 | 9 | 31 | 同一材料家族的另一种包装；不能整个拷入本引擎 |

最重要的澄清：**不能把 28 个 `material-differs` 判定成 28 款材料过时。**

- main 的 20 份胶片仅字节格式不同，规范化内容相同。
- 另外 8 份印相材料，本地额外携带 `data.edr_tone_map`；除该字段外，与 main 相同。这是本地扩展，不是缺失新版测量。
- dev 的 28 个共有材料，`density_curves_model.model_type` 从本地 `cdfs` 改名为 `norm_cdfs`；全部 28 份的 centers/amplitudes/sigmas 数组相同。另有上述 8 份 EDR 差异；没有证据表明这 28 份基础测量被更新。
- 所有共有材料仍声称 `metadata.version=0.3.2`，即使结构/字段已有变化。**版本字符串不能代替哈希。**
- CineStill 800T 没有独立测量数组：本地通过 `derived_from=kodak_vision3_500t` 继承数据，只覆盖名称、用途和无防光晕背层标记。不能将其描述为独立实测 800T 光谱数据。

原始字节哈希与 `spk-audit-v1` 类型化规范流哈希分开：后者按 ordinal 排序对象键、保留数组顺序和 null，将数值规范为 double 的 round-trip 表示，忽略空白、键顺序和 `1`/`1.0` 表示差异；**不是 RFC 8785，也不是图像等价证明**。`material_sha256` 排除 metadata，但包含结构/模型标记；字段哈希用于进一步解释差异。不得把 null 对应的无测量波段一概填零。

| “富士 C400” | 名称不唯一 | Fujifilm 400、Superia Premium 400、Superia X-Tra 400 不应互当别名；先确定具体产品和批次/数据表 | 需产品身份确认 |

film-scan-calibration 实际有 72 份胶片文件和 5 份相纸文件，**不是 77 个完整 Profile**：同一材料分别提供特性曲线、染料、感光度和 MTF；Vision3 还有公共基底/文件名前缀差异。完整文件表见 JSON。

具体不足：Fujifilm400 感光度注明相对纵轴、D-min 上 1.0 的测量，400–700 nm；不能当成 Kodak 的绝对感光度、D-min 上 0.2、250–750 nm。其染料重建注明使用 Vision3 染料作替代基底，并非独立测得的三层染料。Pro400H 没有独立 spectral-sensitivity 文件，Superia X-Tra 400 只有 MTF，其他反转片也不能仅凭 MTF 补齐前向曝光模型。扫描负片反演/校准与本引擎从场景曝光向前模拟并非同一契约；不得移植其反演算法来偷偷改变本引擎。

## darktable 格式兼容性

以实际文件而非 README 示例为准：`pack.json.pack_format=2`，manifest 也为 2；README 示例仍写 1。包内 31 份 Profile、一个 pack.json、一个 LUT，共 33 个 manifest 项。

- 公有 28 份彩色/反转/印相 Profile 与 dev 规范化内容相同，但有 `norm_cdfs` 类型标记。当前引擎按 Gaussian CDF 计算，仍须验证而不是仅凭名字判定。
- 三份黑白材料与 dev **不完全同一规范化内容**。例如 darktable Tri-X 的曲线已变为三列，不能由 README 的“未修改”描述推出全部文件逐字节相同；仍有单通道感光度、null 可选字段与显影时间外轴等兼容问题。
- 引擎要求 `wavelengths=81`（380–780、5 nm）、感光度/染料 `81×3`、基底 `81`、曲线 `N×3`、分层 `N×3×3`。导入器必须检查，而不能靠当前 loader 在首次渲染时才报错。
- `pack.json` 包含 CMF、照明、滤片、中性印相包和逐胶片 grain/halation/coupler 默认值。它们不是只导入 Profile 就会自动生效的字段；本引擎有自己的常量及参数默认值，不能当成同一数据版本。
- `spectra_lut.f32` 虽然后缀 f32，实际头为 **SFS2、header v2、dtype=1（float16）、192×192×81**，标识 `irradiance_xy_tc@0.3.3`，身份 `565f4ec4`。本地为 **SPKR** 容器 `spektrafilm_constants.bin`，包含多张表及颜色常量，布局完全不同。不能重命名文件替换，亦未证明光谱表内容相同。
- 包哈希只锁定数据，不锁定 darktable 渲染代码；完整渲染等价性仍需引擎、默认参数、表及输入约定一起固定。

## 非破坏性实施与回归门

1. 固定原文件、commit、blob、完整 SHA256；转换输入保存在原样存档；输出另起命名空间和 ID。版本变化新增 ID，不覆写旧文件。
2. 先处理单条件 Tri-X Reversal：纯数据表示转换，曝光轴不移动；银密度拆为三份、感光度和曲线重复表示；校验和独立算术测试之后再试渲染。移除 null 可选字段必须逐项记录，不乱填无测量波段。
3. 材料管理层位于文件/目录边界，复用 `load_profile` 和现有目录注册；C API 不需改变。检查尺寸、单调轴、CDF 家族、有限值/有语义的 null、别名依赖、ID、来源/许可和包路径。未知模型拒绝，不默默当成 Gaussian。
4. 使用独立用户目录、原样源/转换版本存档、原子索引和临时运行资源视图；禁用/移除选择项与删除历史版本分开。已有编辑保存 ID 与完整数据指纹；丢失时明确报错，不回退 Portra。
5. 第一款门：owned DNG → 当前 Windows Vulkan → Qt 可选和真实预览 → 保存/重开 → TIFF/JPEG/PNG。检验旧 Portra 同一输入/参数前后输出完全相同；物理默认效果另测，不能用关闭效果冒充默认可用。
6. 校验负门：截断、过大、非法轴/形状、错误通道、未知 CDF、NaN/Inf、null 必要字段、路径穿越、缺来源/许可、冲突/校验和错误和缺失版本；失败无部分安装、不崩溃、不损坏原有库。
7. 首款通过后，才固定显影条件转换 Double-X 和 2302；保留未选条件的原始存档，不擅自增加显影时间插值。calibration 的新增彩片另设研究/拟合阶段。
8. 阶段集成跑完整 Windows CTest、NVIDIA/Vulkan 真实 RAW 和 Qt 控件回归。离屏渲染不是物理窗口点击/显示器验收；Metal 对照在此机器不可运行，明确待外部验证。

后续实际实现/测试/提交另记；此报告的审计结论不能充作新增材料已经可运行的证据。
