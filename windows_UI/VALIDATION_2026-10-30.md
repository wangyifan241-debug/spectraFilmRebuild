# Windows 原尺寸导出增量验证 — 2026-10-30

对应 [移植计划](WINDOWS_PORT_PLAN.md) P0/P1。P1 尚未完整验收，不代表其他阶段已经完成。

## 本轮改动

- `Frame` 保存原始解码尺寸及共享、只读的解码快照；Qt 原图信息不再显示预览尺寸。
- 单张/批量导出从所捕获快照生成 `full` 尺寸，再进行显影后处理、裁切/旋转和用户指定的缩小；不是预览图插值放大。
- 原尺寸渲染不替换编辑器画面。临时释放预览 GPU 会话，下次编辑从保留的解码重建；失败仍保留已显示图片。
- 桌面宿主指定 128 行分条；限制缓冲池的大块复用，避免 12 字节参数占住整幅图的显存块。分配失败时只回收空闲池块并重试一次。
- Vulkan 原始输入/缓存负片优先放到 GPU 可访问的系统内存，工作平面仍使用设备本地存储。不是 CPU 胶片渲染，也没有修改材料数据、精度或关闭效果。

## 第二轮：ProPhoto、全局调色、原图对比和场景节点

用户本轮将 P2–P7 列为优先事项。本轮实际完成的是 P2/P3/P4 的可独立验证部分和 P5 的 Vulkan/C ABI 节点，不是全部移植。

### 实现与边界

- Qt 宿主显式请求编码 ProPhoto 工作色域；旧 Win32/命令行宿主的默认 sRGB 契约不改。帧携带实际色域与独立拥有的输出变换表，不再把 ProPhoto 像素当作 sRGB 显示。
- 将原有 `engine/host/output.cpp` 的色彩算术拆为可共用的 `colour_transform.cpp`，没有另写色域映射。沿用引擎提供的矩阵、TRC 和 CAM16/C_max；表改为独立持有，快照在引擎销毁后仍能输出。可选 `spektralab-host` 目标也实际编译通过。
- 工作顺序：显影后 → 工作色域中的裁切/旋转/拉直/缩放 → sRGB 输出转换 → 位深转换/ICC 文件。转换的临时浮点平面按 128 行限制。
- 全局 Layer 2 新增五条 256 点单调三次曲线、主控/阴影/中间调/高光色彩平衡和暗角；沿用 Mac 处理顺序及 ROMM 中灰 0.3857。色彩平衡目前使用色相/强度/明度滑块，不是圆形色轮控件。前端调色仍在 CPU，胶片模拟仍是 Vulkan；尚无真实窗口拖动性能或 Mac 整图对照结论。
- 编辑文档 v3 存储曲线、分区、暗角及工作域标记；v1 中性迁移，v2 保留旧 sRGB 调整解释。严格拒绝非法曲线、分区、未知版本，不覆盖既有损坏文件。撤销、重做、同步、保存重开、单张及批量输出走共用状态。
- 原图来自帧保留的 scene-linear RAW 解码，在线性域双线性缩小后编码与输出转换，不借用胶片结果。原图/分屏/按住空格均只改变查看方式；共享几何、缩放和平移，不影响文件导出。持久“不应用胶片模拟”模式尚未实现。
- FrameCanvas 读取当前 Windows 显示设备的 ICC，并在纹理上传前做 Qt ICC 转换；获取失败/无效会显示 sRGB 未校准状态。离屏运行不能证明物理显示器、Windows ACM、HDR 或多显示器实际观感正确。
- 场景映射 `spk_scene_latitude.comp` 直接迁移 Metal 节点，保留三个范数、rolloff、阴影提升限制及横/竖双格与分条行原点。移除的只是该功能的 Windows 拒绝分支；Qt 测量、拟合和调节面板仍待实现，边框、日期与双拼工作流仍未完成。
